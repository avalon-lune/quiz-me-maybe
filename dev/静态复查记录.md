## 本轮发现与处理

以下是源码阅读发现及修复，不是实际运行失败或通过记录。

| 编号 | 问题与影响 | 源码处理 | 待执行验证 |
|---|---|---|---|
| SR-01 | 客户端可能先处理已经过期的缓冲回复，或在 select 等待期间越过期限后先收发数据，从而清除超时状态 | `client.py` 在解码之前、select 返回之后检查请求、残帧和写入期限 | `test_client.py` 新增3个边界测试方法 |
| SR-02 | 服务器只写就绪时可能在写阻塞或关闭期限之后再次发送，刷新进度或延长关闭 | `server.py::_write` 先检查期限；待断开的连接不发送，关闭期限前仍可冲刷剩余回复 | `test_transport.py` 新增写截止、关闭期限前后2个测试方法 |
| SR-03 | 新 socket 的非阻塞模式初始化在异常保护之外，失败可能让服务退出、影响已有客户端 | 将 `setblocking(False)` 纳入新连接初始化的异常处理，只关闭该新连接并继续接入 | `test_transport.py` 新增失败连接之后继续接入的测试方法 |

| SR-05 | 真实客户端测试对错误操作和 Ctrl+C 的覆盖不足，部分证据原本依赖 raw peer 或人工计划 | 新增两个实际 client.py 进程的错误恢复/答题边界用例，以及客户端 SIGINT 清理用例；加强最终排行排序、目录保密和每房间计时断言 | `test_client_workflow.py` 新增2个方法；`test_server_integration.py` 加强已有断言 |

## 已知歧义与残余限制

* 学校“1 MB”未说明十进制或二进制；当前采用1,000,000字节。题库 ID 的“letters/digits”未限定 ASCII；当前接受 Unicode 字母数字。可见文本采用可打印字符解释，必需非空文本还要求包含非空白字符。这些解释已在 README 写明，取得进一步说明后需核对。
* 首次记录的极深扩展递归限制已按 SR-07 在源码中处理：容器嵌套使用显式栈，深度不消耗 Python 调用栈；输入仍不得超过1,000,000字节，解析内存随文件内容增长。不能把尚未运行的一万层用例描述为通过。
* 官方镜像的标识、入口、架构及运行细节尚未获得，因此 Python 3.12 实际启动、网络并发、真实终端退出和计时结果均未确认。
